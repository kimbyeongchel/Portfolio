F2치명고치는 비용: 매우 낮음

서버 연결이 TCP로 설정돼 있습니다

증상 같은 방에서 특정 한 명만 유독 수 초씩 늦음 (무선 연결일 때 심함)

근거 설정 확인

Photon/…/Resources/PhotonServerSettings.assetAppSettings:
  FixedRegion: asia
  Protocol: 1                # 0 = UDP (PUN 기본), 1 = TCP
  EnableProtocolFallback: 1

코드에서는 PhotonNetwork.ConnectUsingSettings()만 호출하고 프로토콜을 바꾸는 곳이 없습니다(3곳 확인). 따라서 실제 연결은 TCP입니다.

원인

TCP는 모든 바이트의 순서를 보장합니다. 패킷 하나가 손실되면 재전송될 때까지 뒤따르는 모든 데이터가 대기합니다(Head-of-line blocking). 위치 동기화처럼 "최신 값만 의미 있는" 데이터도 낡은 패킷을 기다립니다.

재전송은 중복 ACK로 빠르게 일어나면 약 0.2초, 재전송마저 손실되면 최소 0.2~0.3초부터 두 배씩 늘어납니다. 손실이 있는 한 명의 연결에서만 멈춤이 생기므로, "그 사람만 늦다"는 증상과 맞습니다. 추정

해결

  • Protocol: 0(UDP)으로 바꿉니다. Photon은 UDP 위에서 Reliable과 Unreliable을 모두 제공합니다.
  • 위치·회전은 Unreliable로 보냅니다. 손실돼도 다음 패킷이 덮어쓰므로 재전송이 필요 없습니다. PhotonView의 Observe 옵션을 Unreliable On Change로 둡니다.
  • 스킬·피격·사망은 Reliable 이벤트로 보냅니다. Photon의 Reliable UDP도 채널 안에서는 순서를 지키므로, 잦은 이벤트와 드문 이벤트는 채널을 나눕니다.

발사라는 입력만 공유하고 명중이라는 결과는 공유하지 않았습니다. 그래서 세 화면이 서로 다른 화살로 서로 다른 물리 시뮬레이션을 돌리고, 그중 마스터 화면의 결과만 데미지가 됩니다.

  • 화살 방향은 RPC에 없고 각 화면이 10Hz로 받은 arrow_dir을 씁니다. 조준을 움직이는 중이면 최대 0.1초 이상 묵은 방향입니다.

이동을 결정하는 주체가 물리 엔진, 애니메이션, 직접 대입으로 나뉘어 있습니다. 같은 프레임 안에서 서로의 결과를 덮어씁니다.

    if (buffered && coyote) {
        vel.y = Mathf.Sqrt(2f * gravity * jumpHeight);  // 즉시 이륙
        lastJumpPressed = -1f;
    }
    var move = grounded ? Vector3.ProjectOnPlane(wish, normal) : wish;
    vel = new Vector3(move.x * speed, vel.y - gravity * Time.fixedDeltaTime, move.z * speed);
    rb.velocity = vel;                                // 쓰는 곳은 여기 하나
}
  • 이동 주체는 둘 중 하나로 정합니다. Kinematic 캐릭터 컨트롤러(속도·중력 직접 적분, CapsuleCast로 충돌 해소)는 액션 게임에서 가장 흔하고, Dynamic Rigidbody를 유지한다면 velocity를 한 곳에서만 씁니다.
  • 경사면에서는 이동 방향만 법선에 투영합니다. 중력을 껐다 켰다 하지 않습니다.
  • 몬스터 머리 위 처리는 위치를 직접 옮기지 않고, 몬스터 콜라이더에 마찰 0 재질과 위쪽 경사를 줘서 물리로 미끄러지게 합니다.
  • 점프 애니메이션은 이륙 후 공중 자세(InAir)에서 시작하고, 예비 동작은 2~3프레임 이내로 줄입니다.

증상 카메라가 따라가는 내 캐릭터가 미세하게 덜컥거림, 설정에서 FPS를 바꾸면 감도가 바뀜

원인

A. 렌더 보간 꺼짐. 물리는 초당 50번, 화면은 60~120번 그려집니다. 보간이 없으면 물리 스텝이 없는 프레임에는 위치가 그대로라서, 카메라가 따라가는 캐릭터가 계단식으로 움직입니다. 120fps에서는 화면 프레임의 58%가 이전 위치를 다시 그립니다.

B. 마우스에 deltaTime 곱. Mouse X 축 값은 이미 "이번 프레임의 이동량"입니다. 여기에 deltaTime을 곱하면 감도가 fps에 반비례합니다. 설정 메뉴의 30/60/90/120fps 옵션 사이에서 같은 손 움직임의 회전량이 최대 4배 다릅니다.

덧붙여 FreezeRotation()이 매 FixedUpdate마다 각속도를 0으로 만들지만, 프리팹에서 이미 회전이 고정돼 있어 할 일이 없는 코드입니다.

F6보통고치는 비용: 중간

원격 캐릭터를 Lerp로 쫓아가서 속도가 출렁입니다

증상 다른 플레이어가 순간적으로 빨라졌다 느려짐, 회피할 때 모서리를 잘라먹음

근거 코드 확인

직렬화 주기는 번들된 PUN 소스의 기본값 100ms(10Hz)이고, 코드에서 바꾸는 곳이 없습니다.

원인

0.1초마다 한 번 바뀌는 목표를 지수 감쇠로 쫓으면, 패킷 직후에는 빠르고 다음 패킷 직전에는 느립니다. 이론상 시간 지연은 1/k = 0.1초에 갱신 간격 절반 0.05초를 더한 값입니다.

냉정하게 말하면 Lerp는 지연의 주범이 아닙니다. 수 초짜리 지연은 F1·F2에서 나옵니다. Lerp의 진짜 문제는 움직임의 모양(속도 리듬, 경로)을 망가뜨린다는 점이고, 그 결과 마스터가 판정하는 위치와 다른 사람 화면의 위치가 달라집니다.

해결

F10낮음고치는 비용: 낮음

IK는 궁수 조준 한 곳에만 있습니다. 발 IK와 지면 정렬(OnAnimatorIK, TwoBoneIK)은 사용처가 없습니다.

원인과 해결

가중치는 자세를 섞는 비율이라 순간 전환하면 자세가 순간이동합니다. 목표 가중치만 정하고 실제 값은 시간에 따라 따라가게 합니다.

rigWeight = Mathf.MoveTowards(rigWeight, target,
                              Time.deltaTime / 0.15f);
aimRig.weight = rigWeight;

Multi-Aim Constraint를 척추·가슴·머리에 나눠 걸고(예: 0.3 / 0.3 / 0.4) 상체가 함께 돌게 하면 더 자연스럽습니다. 발 IK를 넣는다면 발밑 레이캐스트로 발 위치를, 두 발 중 낮은 쪽만큼 골반을 내립니다.

04잘한 점과 멈춘 리팩터링

냉정하게 봐도 방향이 맞았던 부분이 있습니다. 면접에서는 이 부분을 출발점으로 삼아 "지금이라면"을 이어 말하면 됩니다.

  • 전사 콤보의 판정 구간. AnimationState ScriptableObject에 impactStartTime을 두고 WindUp → Impact 단계로 판정을 엽니다. 현업에서 프레임 데이터로 공격 판정을 관리하는 방식과 같은 발상입니다.
  • 경사면 처리. ProjectOnPlane으로 이동 방향을 지면에 투영하고, 다음 위치를 미리 레이캐스트해 급경사를 막았습니다. 방향은 맞고, 중력 토글만 걷어내면 됩니다.
  • 데이터 분리 시도. 스탯과 쿨타임을 State ScriptableObject로 뺐고, 인터페이스 5종(IUnitStats, IMove, ISkill, IDamageable, IEffect)을 만들었습니다.
  • Animation Rigging 도입. 궁수 조준에 리깅을 쓴 것 자체가 졸업 작품 수준에서는 드뭅니다(F10의 블렌드만 추가).

멈춘 리팩터링 · 방향은 정확

RefactoringScript/Script/class/에 시작했던 작업이 있습니다. Input System 기반 PlayerInputManager, 그리고 PlayerMovement·SkillManager·HealthSystem·UIManager·CameraControl로의 분리입니다. 단일 책임 원칙 방향으로 정확히 가고 있었습니다.

그 안에 남은 문제

  • 람다 구독 해제 버그. Left.started -= i => { isLeft = true; };는 새 델리게이트라 아무것도 해제하지 않습니다. 오브젝트가 꺼졌다 켜질 때마다 핸들러가 누적됩니다.
  • 파일만 나뉘고 의존은 그대로. Movement, Skill, Health가 서로를 GetComponent로 찾습니다. 의존 방향이 한쪽으로 흐르지 않습니다.
  • 이름은 공통, 내용은 전사 전용. SkillManager가 검 콜라이더를 직접 참조합니다.
  • 입력을 유지값 bool로만 노출. "이번 프레임에 눌림" 정보가 사라져 점프 버퍼 같은 기능을 만들기 어렵습니다.
